# Robinhood Chain 日度雷达：数据口径

状态：已实现
链：Robinhood Chain mainnet，chain ID `4663`

## 产品边界

这是一个独立、只读的数据监控器。它不读取钱包，不加载 Bankr API Key，不构造交易，
不签名，也不广播。历史 `runs/`、CSV、配置和图片仅作为旧项目证据保留，程序不会读取它们。

默认观察最后一个已结束的 UTC 自然日（T-1），并把每个指标自己的实际数据日、延迟天数、
来源和抓取时间一起展示。来源失败时显示 `UNKNOWN`；不会用旧快照填充成新数据。

## 回答的核心问题

1. Robinhood Chain 的使用量、用户规模和吞吐是否增长？
2. 稳定币、DeFi TVL、股票代币等资本是否沉淀？
3. 链手续费、L1/DA 成本、链上利润和应用收入是否改善？
4. 与 Base、Arbitrum、Optimism、World Chain、Plume 相比处在什么位置？
5. 数据是否足够新、来源之间是否存在显著分歧？

## 第一版指标

| 维度 | 指标 | 主来源 | 时间口径 |
|---|---|---|---|
| 使用 | 日交易数、日活地址、Gas/s、中位交易成本 | Growthepie | T-1 或更早的最后可用完整日 |
| 资本 | 稳定币供应、Total Value Secured、DeFi TVL | Growthepie、DefiLlama | 日度；Defi TVL 为抓取时快照 |
| 经济 | 用户支付 Gas、L1/DA 成本、链上利润、应用收入 | Growthepie | T-1 或更早的最后可用完整日 |
| 市场 | DEX 成交量、协议费用、协议收入 | DefiLlama | T-1 或更早的最后可用完整日 |
| RWA | 活跃股票代币数、估算代币化价值 | Robinhood 官方资产/报价 API + `totalSupply()` | 最新抓取快照，不伪装成 T-1 |
| 健康 | 官方状态页、Blockscout 统计 | 官方状态页、Blockscout | 最新抓取快照 |

Growthepie 字段 `tvl` 的官方名称是 **Total Value Secured (TVS)**，不是 DeFi TVL；
DefiLlama 的链 TVL 才标为 DeFi TVL。Growthepie `fees_paid_usd` 在本项目中写成
“用户支付 Gas / 链手续费”，避免把它误读成协议收入。

## 股票代币估值

对 Robinhood 官方资产列表中 chain ID 4663 的活跃部署，以公共 RPC 批量只读调用
`totalSupply()`，并用报价中间价估算：

```text
estimated_value_usd = totalSupply / 10^tokenDecimals
                    × (bid + ask) / 2
                    × currentMultiplier
```

报价或 RPC 任一侧缺失的资产不进入估值，并在覆盖率中披露。该值是观察指标，不是审计后
资产净值，也不应用于交易决策。

## 横向比较

- 固定同屏：Robinhood、Base、Arbitrum、Optimism、World Chain、Plume。
- Growthepie 指标还计算其已跟踪扩容链中的降序排名和分位数。
- 排名只使用与 Robinhood **同一数据日** 的数值，避免把不同日期混排。
- DEX/协议指标只做固定同屏比较；不同适配器口径可能不完全一致，因此展示来源而不合成
  一个不透明总分。

## “好还是坏”的基准模型

看板使用 `benchmark-v1` 回答“Robinhood Chain 的生态基本面现在处于什么状态”，不回答
代币是否便宜、是否值得买卖。模型不输出加权总分，而是保留四个可独立核验的维度：

1. **市场位置**：固定六链同日排名 + Growthepie 全部已跟踪 L2 分位；
2. **自身趋势**：同一指标相对 7 日前和 30 日前的变化；
3. **增长质量**：不同维度是否互相确认，尤其检查交易数与活跃地址是否背离；
4. **数据可信度**：核心指标覆盖、新鲜度、UNKNOWN 数量和来源失败数。

### 市场位置

- 同日分位 `>= P70` 记为领先带，`<= P30` 记为偏弱带，其余为中位带；边界值包含在内。
- 固定同行与全部 L2 一强一弱时记为“基准分化”，不会用其中一个覆盖另一个。
- 至少 4 个核心指标可比较才生成总体位置；半数以上核心指标领先且偏弱项少于四分之一，
  总体位置才记为“领先”。偏弱判定使用对称规则。
- 中位交易成本是成本指标，下降视为改善；但卡片始终保留原始涨跌，避免反转含义后失真。
- L1/DA 成本是解释链经济性的背景项，不作为链本身“好坏”的直接得分项。

### 自身趋势

趋势阈值按指标波动属性设置，只有超过阈值才视为方向变化：

| 指标类型 | 7 日阈值 | 30 日阈值 | 包含指标 |
|---|---:|---:|---|
| 资本存量 | 3% | 8% | 稳定币供应、TVS |
| 高波动市场 | 15% | 25% | DEX 成交量、协议费用、协议收入 |
| 其他核心指标 | 5% | 10% | 交易、活跃地址、吞吐、费用、利润、应用收入等 |

- 7 日和 30 日都向上：`持续扩张`；都向下：`持续放缓`。
- 7 日向上、30 日未确认：`短期反弹`；7 日向下、30 日未确认：`短期转弱`。
- 两个窗口都没有越过阈值：`稳定`；缺数、延迟或不可用：`UNKNOWN`。
- 总体趋势必须由多个核心指标共同确认；例如“持续扩张”要求至少半数核心指标持续扩张，
  且转弱项少于四分之一。

### 增长质量与数据闸门

- 交易数与活跃地址 7 日方向相反时，直接标记“增长分化”：活动规模与用户广度没有互相确认。
- 四个维度同时改善才可能标记“广泛改善”；扩张与放缓并存时保留“增长分化”。
- 数据可信度为低时，总结必须显示 `UNKNOWN`，不得继续判断基本面好坏。
- 高可信度要求：来源无失败、无不可用核心指标、延迟核心指标不超过 1 项、核心覆盖率至少
  90%；中可信度允许最多 2 个来源失败、3 个不可用、3 个延迟且覆盖率至少 60%；其余为低。
- 主网上线不足 90 天时，90 日结构性基准明确显示 `UNKNOWN`，不会用不足 90 天的样本冒充
  长周期基准。

单项标签由“位置 × 趋势”组合产生。例如：领先且持续扩张为“强”，领先但持续放缓为
“领先转弱”，偏弱但持续扩张为“追赶改善”。这类标签只压缩表达，原始排名、分位、
7/30 日变化和来源仍同时展示。

## 新鲜度和质量规则

- `ok`：实际数据日与目标日相差 0–1 天。
- `stale`：相差 2 天或更多。
- `unavailable`：没有可解析的数值。
- 当前快照型指标标 `live`，不会参与 T-1 排名。
- 原始响应以逐来源 gzip 写入 `data/raw/<run-id>/`，标准快照写入 `data/snapshots/`，日报写入
  `reports/`；写入使用临时文件加原子替换。
- 所有持久化错误信息都经过 URL 凭证清洗。

## 运行

```bash
npm run daily             # 采集 + 生成中文日报
npm run serve             # http://127.0.0.1:4173
npm run collect -- --date 2026-08-23
npm run report -- --date 2026-08-23
```

推荐每天北京时间 15:00 执行 `npm run daily`，等待上游完成 T-1 回填。
