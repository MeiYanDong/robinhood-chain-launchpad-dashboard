# PAIR Alpha 跨代雷达

版本：0.14.8（本地实现）
范围：PAIR V1/V2 的只读发现、动作分流和可复核 Shadow 回放。

## 为什么单独做一页

`/pair-v2/` 回答“当前 canonical release 发生了什么”，不应该拿历史 V1 目录身份冒充当前
release 的链上发行凭证。但只看当前 V2 会漏掉仍在活跃、甚至突然爆发的旧代际项目。
`/pair-alpha/` 因此回答另一个问题：全代际里，哪些项目刚出现承接，哪些正在回踩，哪些已经
过热不能追，哪些因为身份或风险证据不足必须停止。

这两个页面共用采集和 SQLite，但输出合同隔离：机制账本不会被 V1 稀释，跨代机会也不会被
限定在 V2。

## 发现与更新架构

```text
PAIR 官方全量目录（60s） ── V1 / V2 / marketVersion / canonical pools
                │
                ├─ 所有 V2
                ├─ 最近 72h 的 V1
                └─ 达到成交或市值门槛的活跃 V1
                              │
                              ▼
                 行情候选池（最多 240 个旧代际候选）
                              │
               5m / 1h / 6h / 24h 活跃度排序
                              │
                              ▼
               热候选池（最多 72 个，每 15s 更新）
                              │
           canonical pool 匹配、模型分层、生命周期账本
                              │
                 ┌────────────┴────────────┐
                 ▼                         ▼
             `/pair-alpha/`         状态跃迁式飞书告警
```

链上当前 release 事件仍每 8 秒更新。完整市场轮询负责重新发现项目、重选候选和渐进更新持币
地址；热行情轮询只读取已经入池项目的官方 canonical pools，避免每 15 秒重抓整个目录。

## 身份证据不是一回事

| 层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| PAIR 官方目录 | 该地址被 PAIR 官方产品索引，适合进入跨代观察 | 不等于当前 V2 release 发行事件 |
| 当前 release 链上事件 | 项目由已认证 coordinator 在当前 release 发出 | 不等于团队可靠或代币值得买 |
| canonical pool 行情 | 官方池的量价、买卖笔数和可见流动性 | 不等于真实净买入资金或可按屏幕价退出 |
| Shadow 模型 | 当时证据落在哪个研究动作通道 | 不等于交易指令、仓位或未来收益 |

V1 只有官方目录身份时，单币风险至少为 medium；缺少身份锚点、被隐藏或标记时直接进入
风险停止。

## 动作通道

动作互斥，避免一个项目同时显示“机会”和“危险”：

1. `risk_halt`：身份或官方风险闸门失败。
2. `no_chase`：拥挤过热，或 5m、1H、6H、24H 涨幅越过爆发阈值。
3. `confirmed`：质量、承接、时机和高置信证据同时通过。
4. `probe_eligible`：达到人工研究门槛，但仍需核验滑点、退出深度和项目风险。
5. `retest_watch`：回撤后短周期买盘重新占优。
6. `ignition_watch`：成交速度或同龄分位刚出现点火。
7. `evidence_wait` / `cold_watch`：行情证据不足或尚无催化组合。

页面不会给“埋伏价格”。更合理的用法是先在点火/回踩通道发现项目，再人工核验合约权限、
创建者历史、持仓集中度、真实可退出深度和事件催化；已经大涨的项目即使成交强，也进入
“过热勿追”。

## 多池成交量怎么读

一个代币可能同时有多个官方池。页面把以下数字分开：

- 官方 24H：PAIR API 的项目级口径；
- 主池 24H：按可见流动性选择的最大 canonical pool；
- canonical 池毛额：所有可匹配官方 poolId 的成交额相加；
- 共识价格：按各池可见流动性计算加权中位价格；
- 跨池价差：canonical pools 的最高与最低可见价格差。

共识价格和价差会排除低于 `$25` 且低于主池流动性 `1%` 的尘埃池，防止几乎无法成交的池子
制造天文价差；尘埃池仍保留在池数量与成交毛额证据中，不会被静默删除。

池成交毛额会同时包含买和卖，不能当成净资金流入。当前没有逐地址、逐 quote asset 的完整
资金流归因，因此 `netQuoteInflowUsd` 固定为 `UNKNOWN`，不会拿成交量猜净买压。

## 首次信号与验证

SQLite 分别保存首次发现、首次点火、上次动作和动作迁移。每个模型版本只冻结第一次有效
动作信号及当时价格，随后在 5m、30m、2H、6H、24H 取目标时点之后的首个有效快照。
回放不会用事后高点重写入口。

回放只扣双边平台费，尚未计入滑点、Gas、MEV 和真实可退出深度。至少积累 14 天与 100 个
24H 成熟样本后才进入人工复核门槛；达到门槛不会自动变成可交易系统。

## API 与安全边界

| 路由 | 行为 |
| --- | --- |
| `GET /api/pair/alpha` | 跨代概览、候选、动作、成交证据和回放 |
| `GET /api/pair/alpha/health` | 自治轮询、时效与告警队列状态 |
| `GET /api/pair/alpha/tokens/:address` | 单币身份、生命周期、动作原因和多池证据 |
| `POST /api/pair/alpha/refresh` | 受限手动完整刷新；公网单独限流 |

日常更新由服务器进程内的 8 秒链上、15 秒热行情和 60 秒完整目录定时器完成，不依赖浏览器
或本地 Codex 任务。模块不读取钱包、不保存私钥、不签名、不广播，也没有自动交易接口。
