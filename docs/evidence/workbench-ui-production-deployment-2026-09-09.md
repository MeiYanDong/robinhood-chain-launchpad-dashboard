## 查询可用性修正

视觉验收暴露了一个原有的查询空窗：collector 忙碌时，未预热的旧总览和刚超过 60 秒的缓存
可能在首屏返回 503。最终版本在交付前完成以下修正：

- 预热清单覆盖 20 个运行时只读合同及决策页默认请求，共 26 个固定 GET 路径；不缓存 POST。
- 成功缓存 60 秒内直接返回。超过 60 秒但不超过 5 分钟时立即返回最后一次成功结果，并在
  响应头写入 `x-ledger-query-stale: true`，同时后台重试。
- 超过 5 分钟仍无法更新时继续明确返回 503；缺失值不补零，响应本身的观测时间、来源状态和
  stale 标记保持不变。

`0.19.0`、`0.19.1` 和 `0.19.2` 是本次上线过程中用于定位上述问题的中间 release，不是最终
交付版本。`0.19.2` 的首次公网运行验证捕获过一次旧总览 503 和一次 PAIR 项目方发行首读 503；
两处均在 `0.19.3` 中修正并重新验收，没有把失败记录成成功。

## 尚未消除的限制

- `partial`、`UNKNOWN` 和来源失败仍按实时来源显示；界面可用不等于第三方数据已经补齐。
- 主机约 1.6 GiB 内存且无 swap，最终观察时 collector 约 861 MB；collector 与 query 仍共享
  同一主机。5 分钟兜底解决短暂刷新空窗，不是长期 SLA，也不等于完整故障域隔离。
- 若最终版本出现查询层回归，可先回到 `0.19.2`；若要撤销整批视觉重构，回到上述 `0.18.1`
  release，并重启 collector 与 query。当前没有触发回滚。
