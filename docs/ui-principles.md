# 数据工具界面原则

## 默认视图

- 只展示完成当前判断所需的数据、控件、状态和会改变判断的警告。
- Robinhood Chain 发射台首页只回答三个问题：谁的成交量最大、谁相较自身历史常态最活跃、PAIR
  当前价格相对“按 PONS 平台规模折算的 PAIR 参考价”是溢价还是折价。
- 发射台拆成四个可分享的任务视图：今日概览、平台经营、PAIR vs PONS、平台代币；不在同一
  长页中堆叠四种任务。
- 主流平台以平台注册表中的 `live` 状态为准；其余平台通过“全部”查看。
- 桌面端使用紧凑表格；移动端优先保留三个结果和任务入口，宽表可在所属任务内部滚动。
- 估值主判断区只显示 PAIR 实际价、按 PONS 平台规模折算的 PAIR 参考价、溢价或折价和当前能否参考；公式、逐项代入和每日
  历史保留在同一任务页，研究情景默认折叠。
- PONS 七日预测必须同时满足相似样本和回测误差门槛才显示结果；否则只显示停用原因，不展示
  中枢、区间或上涨概率。
- 全局导航只切换产品模块；发射台内部使用“今日概览 / 平台经营 / PAIR vs PONS / 平台代币”
  的任务导航。
- 平台活跃度只和平台自身历史比较；主界面说“相较自身历史常态”，并用问号说明分子、分母和 1.0× 的含义；样本、覆盖、百分位等研究字段按需展开。
- 主界面的日度指标必须直接展示具体日期，例如“9月7日交易量”；“闭合日”只属于数据处理过程，不作为用户标签。
- Pons、Long、PAIR 使用一套全站颜色映射。图例、卡片、表格、曲线和数据点不得分别定义颜色；曲线应尽可能直接标注平台名。
- 首页绝对交易量使用线性坐标，确保视觉高度与金额比例一致；平台自身趋势另由活跃度页面表达。
- 7 日、30 日窗口不完整时只展示已观测下限；上线以来只展示规模，不跨上线日期计算份额。
- PAIR Alpha 首屏只展示当前动作通道、关键短窗数据、代际和风险；V2 当前 release 的机制与
  链上账本留在 `/pair-v2/`，跨代机会不混回机制页面。

## 按需信息

- 指标口径、来源健康、计算限制和平台审计说明必须保留，但默认折叠或放入“数据说明”。
- 平台详情默认展示三个核心指标和历史；范围、备注、来源链接放在折叠区。
- 通用 `Revenue` 继续保留在数据层，不进入默认界面，避免与平台收入混淆。
- 正常的官方、链上和第三方来源使用低噪音标记；范围不同、未核验、过期和不可用必须保持显著。

## 不进入产品界面的内容

- 宣言、口号、价值观式标题和装饰性章节编号。
- 重复解释当前页面已经能直接表达的内容。
- 中英双语包装标签、纯装饰副标题和方法论长文。
- 不会改变当前判断的覆盖率、来源或计算说明。
- 用于制造紧迫感但不能改变动作的涨幅口号；涨幅只能作为“过热勿追”或风险证据。

## 验收

- 用户打开首页后，无需阅读说明即可读懂三个结果，并能进入正确的后续任务。
- 主界面不出现“闭合日”“相对平时”“PONS 规模参考价”“现价锚”等需要二次翻译的标签。
- 首页不存在宣传性文案；错误和数据异常仍然明确可见。
- “数据说明”和平台详情能够追溯口径、来源及限制。
- 375px 宽度下页面本身不横向溢出；只有明确标识的任务内宽表允许局部滚动。
- 移动端全局入口固定在底部，页面内数据集保留在内容顶部，避免连续两排全局导航。
