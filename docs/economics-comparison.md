# Pons / Long / PAIR 三强对比

## 目标

数据层回答三类问题：代表币现在值多少、平台当天做了多少生意、回购是否真的执行。产品首页
只提炼成交量龙头、相对平时最活跃的平台和 PAIR / PONS 规模参考结果；完整经营、估值、代币
与回购证据进入各自任务页。三类数字分开建模，缺证据时保持未知。

## 代表币

| 平台 | 代表币 | 选择规则 |
| --- | --- | --- |
| Pons | PONS | 固定协议币 |
| Long | 当前市值龙头 | 从已通过 LongLauncher 归属核验的活跃样本动态选择 |
| PAIR | PAIR | 固定协议币 |

三种代表币都显示市场数据源直接报告的当前美元价格；不使用“市值 ÷ 供应量”反推价格。
PONS 和 PAIR 同时显示两种市值：市场来源市值，以及
`价格 ×（链上 totalSupply − 0x…dead 累计余额）`。后者是销毁调整口径，不覆盖其它锁仓、
跨链或流通限制。

## 平台经营

市场份额的分母固定为 Pons、Long、PAIR 同一闭合 UTC 日的成交量之和。三家任意一家缺数，
当天份额不计算；不会用不同日期、滚动 24H 或代币交易量拼接。

用户手续费、协议收入应计、协议金库实收、理论回购预算、实际回购、回购后留存和净利润均是
独立字段。一个字段存在不能自动推出另一个字段。

## 回购证据

- 政策比例：公开文档或公告描述的分配规则；
- 理论预算：协议收入应计值乘政策比例；
- 累计销毁：链上销毁地址余额；
- 实际回购：必须能核验资金来源、Swap 输出和销毁或锁仓去向；
- 净利润：还需要运营成本、市场支出、工资和税费，当前不做估算。

Pons 与 PAIR 在没有逐笔闭环证据时只展示政策和累计销毁，不把二者写成实际回购。Long 没有
回购机制，相关字段是“不适用”，不是 `$0`。

## PAIR 相对估值

中心值只回答一个问题：如果 PAIR 获得与 PONS 相同的“平台成交量对应代币价值倍数”，PAIR
每枚代币对应多少美元。

```text
PONS 当前价格
×（PONS totalSupply − PONS 累计销毁）
÷（PAIR totalSupply − PAIR 累计销毁）
×（PAIR 最新共同完整 UTC 日成交量 ÷ Pons 同日成交量）
```

- 主参考固定使用最新一个双方都有平台成交量的完整 UTC 日；该日缺失时停止计算；
- 最近 7 个共同完整 UTC 日只生成平滑对照和逐日结果的 P25–P75 区间；
- 缺失日不补 0，来源明确报告的 0 才保留；
- PONS 价格必须在 30 分钟内更新；PAIR 实际价格不进入中心，只计算实际相对中心的偏离；
- 区间是窗口内逐日同公式结果的第 25 与第 75 百分位；
- PONS 80% 与 PAIR 90% 的手续费分配比例只生成“其它条件不变”的独立政策情景；
- 置信度由共同历史长度、窗口完整度、成交量质量和 PONS 价格来源共同决定。

界面把中心值称为“按最新完整日平台量折算的 PAIR 参考价”，把实际偏离写成“PAIR 当前溢价 /
折价”。共同历史不足时标记“谨慎参考”或“暂不参考”；7 日平滑值明确作为对照，不与单日主
参考混成一个结果。区间、费用比例情景和研究置信度不进入主判断区。

每次经济快照把中心值、区间、输入、共同日期、原因码和模型版本写入完整快照，并把绘图所需
字段写入独立紧凑历史表。旧值是历史观测，不会在当前输入失效时冒充实时结果。

## API

- `GET /api/economics`
- `GET /api/economics/health`
- `GET /api/economics/valuation`
- `GET /api/economics/valuation/history`
- `GET /api/economics/sources`
- `POST /api/economics/refresh`

快照保存在同一个 SQLite 文件的独立 `economics_snapshots` 表，估值绘图点保存在
`pair_relative_valuation_snapshots` 表。外部来源失败时保留上次快照并
标记过期；公开刷新接口会协调底层来源。生产环境另用仅允许回环访问的
`POST /api/economics/rebuild`，在 PAIR、Long 定时刷新后错峰重建快照，公网 Nginx 固定返回
`403`。所有刷新都只读，不接触钱包、签名或交易。
