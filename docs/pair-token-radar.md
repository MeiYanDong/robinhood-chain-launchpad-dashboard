# PAIR 代币雷达

## 用户看到什么

PAIR 代币页展示四张独立 Top 5：市值、流动性池深度、滚动 24H 交易量和持币地址。
“实时榜”比较最新快照与最近一份日报；“08:00 日报”比较连续两份日报。排名变化为正表示
上升，负表示下降。没有基线时显示 `—`，不把它写成新上榜。

四项指标不合成一个总分。某项缺失只会使代币退出该项排名，不影响其它三项。

## 数据边界

PAIR 官方 API 是代币发现、市值、流动性和交易量的主源。每次采集先读取第一页中的
`total`，再抓取所有分页；缺页、重复结构错误或无有效代币时整次失败，不用残缺分页生成榜单。

入榜候选必须同时满足：

- 市值不少于 `$10,000`；
- PAIR 全部官方池的美元深度合计不少于 `$1,000`；
- 官方市场数据更新时间距离采集不超过 60 分钟。

以上阈值是候选集规则，不是投资建议。数据库仍保存全量代币身份，但只有候选集写入排名快照。

持币地址来自 GMGN `token info` 的 `holder_count`。正常缓存 60 分钟；刷新失败时最多沿用
150 分钟内的旧观测并将整次运行标为 `partial`，更旧的值保持未知。
项目将 `gmgn-cli@1.5.2` 固定为生产依赖，systemd unit 使用 release 内的绝对可执行路径，
避免服务器的全局 PATH 或 CLI 版本漂移改变采集结果。

## 调度

- `robinhood-chain-pair-refresh.timer`：每小时第 00、15、30、45 分钟刷新实时榜；
- `robinhood-chain-pair-daily.timer`：每天 `00:10 UTC`，即北京时间 08:10，固化截至 08:00
  的最近可用快照；
- 日报选取不晚于 08:05 的快照；快照距离 08:00 超过 30 分钟时明确标为 stale。

两种定时任务都只向监听在 `127.0.0.1:4175` 的服务发 POST。公网 Nginx 对手动刷新限流，
并直接拒绝日报生成路由。

## 失败行为

- PAIR 官方 API 失败：本次运行失败，继续提供上次成功快照；
- GMGN 部分失败：市场三榜继续更新，持币榜使用有时限缓存或排除未知项，运行标为 partial；
- 日报时点没有可用快照：不生成空日报，不覆盖上一份日报；
- 缺失值与明确的零值严格分开，任何来源失败都不会转换为零。

该模块只读，不访问钱包、不签名、不广播交易。
